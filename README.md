# ParaBank E2E (портфолио)

![Tests](https://github.com/KSO48/parabank-e2e/actions/workflows/tests.yml/badge.svg)

Playwright + TypeScript тесты для [ParaBank](https://parabank.parasoft.com) —
публичного демо-банка от Parasoft, официально созданного для практики
автоматизированного тестирования. Написано с нуля специально для портфолио —
в отличие от корпоративных проектов, здесь весь код полностью свой,
без ограничений на публикацию.

## Стек
- Playwright + TypeScript
- Обычный headless Chromium — никакого спецбраузера/плагинов не нужно
  (в отличие от проектов с реальным ЭДО-подписанием документов)

## Что покрыто

- **`tests/customerJourney.spec.ts`** — полный путь клиента: регистрация →
  чтение номера автоматически созданного счёта → открытие второго счёта →
  перевод средств между своими счетами → повторный логин.
- **`tests/loanRequest.spec.ts`** — заявка на кредит с двумя исходами
  (Approved/Denied) в зависимости от соотношения суммы взноса и доступного
  баланса — ближайший на этом сайте аналог сценария "заявление → решение".

## Особенности сайта, из-за которых тесты не так тривиальны, как кажется

Ничего из этого не было очевидно из документации — каждая находка
подтверждена ручной проверкой реального DOM/сетевых запросов перед тем,
как попасть в код (см. комментарии в `tests/helpers/parabankFlow.ts`):

1. **Нечёткая проверка уникальности username.** Любой логин с префиксом
   вроде `qa_`, `test_`, `e2e_` стабильно получает "This username already
   exists.", даже если такая строка гарантированно нигде не встречалась —
   сайт много лет служит публичным полигоном для QA-практики со всего мира,
   и его проверка уникальности, похоже, работает как нечёткое совпадение по
   подстроке, а не точное сравнение. Решение — генерировать логин без
   узнаваемого префикса (`tests/helpers/testData.ts`).
2. **CSS-локатор `#customer.firstName` — ловушка.** Точка после `#` в CSS
   означает класс, а не часть id — `#customer.firstName` резолвится в
   "id=customer, класс=firstName", а не в элемент с id
   `"customer.firstName"`. Нужен атрибутный селектор `[id="customer.firstName"]`.
3. **`baseURL` с путём + `page.goto('/x.htm')` = потерянный путь.** Ведущий
   слэш в относительном пути при резолвинге URL сбрасывает путь из
   `baseURL` до корня домена (WHATWG URL rules) — `baseURL:
   'https://host/parabank'` + `goto('/register.htm')` даёт
   `https://host/register.htm` (404), а не `.../parabank/register.htm`.
   Фикс — слэш на конце `baseURL` и пути без ведущего слэша в `goto()`.
4. **Открытие счёта — реальная гонка на стороне сайта.** Список счетов для
   перевода стартового депозита (`#fromAccountId`) заполняется отдельным
   AJAX-запросом уже после рендера страницы; обработчик клика "Open New
   Account" читает результат этого запроса без проверки на `null` — клик
   раньше, чем список успел подгрузиться, тихо ничего не делает (без
   ошибки, без исключения на экране). Тест явно ждёт, что список реально
   заполнился, прежде чем нажимать кнопку.
5. **AJAX-результаты не меняют URL.** И "Open New Account", и "Apply Now"
   (заявка на кредит) — `<button type="button">`, подменяющие контент через
   AJAX без навигации. Проверка результата — через ожидание конкретного
   текста/появления элемента, а не `waitForURL`.

## Запуск

```bash
npm install
npx playwright install chromium
npm test
```

Каждый прогон создаёт своего уникального пользователя — сайт публичный и
общий для всех, кто его тестирует, поэтому изоляция теста держится на
уникальности сгенерированных данных, а не на выделенном окружении.
